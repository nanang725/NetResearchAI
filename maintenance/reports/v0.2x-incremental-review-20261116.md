### 5.4 文献发现与 arXiv

**实际实现**

- `arxiv_service.py` 调用 arXiv 官方 Atom API，限制 3 秒请求间隔、15 秒超时、最大 50 条，禁用 DOCTYPE/ENTITY。
- `discovery_service.py` 支持搜索、官方元数据复核、收藏、PDF 下载、现有 ImportJob 入库、关键词追踪、历史新增计数和外部/本地推荐。
- API 前缀 `/api/discovery`，含 search、favorites、favorites/import、tracking、tracking/refresh、recommendations。

**数据流**

`arXiv Atom -> ExternalPaper -> ExternalFavorite/TrackingSearch -> TrackingRun/Seen/Item`。PDF 入库：下载并校验 `%PDF` -> SHA 去重 -> demo/正式配置的 `.imports` -> 现有 ImportJob Worker。

**接入状态**

真实接入现有 ImportJob 和 RAG，不使用 Mock 业务结果。

**测试**

- `test_discovery_api.py`：11 个测试，覆盖 Atom 解析、分页、超时/限流、收藏复核、哈希去重、下载失败、导入任务、追踪历史和推荐来源区分。

**确认缺陷**

`discovery_service._serialize_favorite()` 将 ImportItem 成功终态判断为：

```python
if item.status == "completed"
```

现有 Import Worker 对单条成功项实际写入 `status="succeeded"`，Job 才是 `completed`。因此收藏记录刷新后可能显示 `succeeded`，而没有映射成 `imported`。

**其他缺口**

- 追踪仅支持手动刷新，没有定时调度。
- 推荐种子只取最近追踪或收藏，未实现排序评估和用户偏好建模。
- 没有取消追踪、取消收藏或删除收藏的 API/UI。
- 真实 arXiv 网络连通性没有被离线测试直接证明，当前测试主要 Mock 上游。

**状态**：主要闭环完成，存在一个用户可见状态映射缺陷。

### 5.8 Research Agent

**实际实现**

- 持久化运行、节点、工具调用、证据和最终交付物。
- `ToolSpec` 白名单注册表；参数和输出均 Pydantic 校验。
- LLM Structured Planner、DAG/循环/预算验证和保守降级计划。
- 依赖驱动的 Executor，单运行单执行线程，只读工具，重试、取消、预算和时间限制。
- 本地证据要求真实 paper/page/chunk 与内容哈希；外部 arXiv 仅允许摘要，不允许伪造页码。
- 本地证据不足时动态追加 arXiv；本地命中足够时动态追加证据大纲。每运行最多一次重规划。
- 只有存在运行时有效来源时才允许 completed。
- API 和前端页面完整注册。

**调用链**

`POST /api/research-agent/runs -> Planner -> validate_plan -> persisted nodes -> Executor ready-node selection -> ToolRegistry -> existing services -> evidence validation -> controlled replan -> report artifact`。

**测试**

- `test_research_agent.py`：12 个测试。
- 最近一次定向执行证据：`12 passed, 6 warnings in 26.03s`。
- 覆盖未注册工具、参数、循环、预算、真实适配器、失败记录、动态外部搜索、外部摘要页码拒绝、伪造 ID、取消、无来源报告和 API。

**风险**

- 后端用进程内 daemon thread 执行；服务重启后没有对中断的 AgentRun 自动续跑。
- 取消不会强制终止已进入同步适配器的当前调用，只保证不再启动新节点。
- Planner/报告真实 LLM 质量和外部网络完整闭环仍缺真实运行验收。
- 未做多用户认证、租户隔离或多运行资源公平调度。

**状态**：第一版只读自主 Agent 核心闭环完成，属于 v0.4.0。

## 13. 最终总体结论

本次增量不是简单的 v0.2.x 小修，而是一次跨越多个版本主题的大型功能扩展。以下主干能力已经真实接入现有业务：

- 本地引用数据与图谱。
- arXiv 发现和入库任务。
- 多文献证据综述。
- 证据化大纲与 References。
- CSV 统计图表。
- 结构化阅读与双向翻译。
- 第一版持久化只读 Research Agent。

当前前后端形成完整闭环的主要功能是：

- 引用图谱。
- 多文献综述。
- 学术写作/References/CSV 工作台。
- 论文结构化阅读与翻译。
- Research Agent。
- 文献发现主流程。

当前不能作为“完整完成”的主要是：

- Discovery 入库终态标签。
- 多论文 Agent 问答前端入口。
- 真实引用边覆盖。
- 完整写作编辑器与导出。
- Research Agent 恢复、生产调度和真实 LLM 验收。
- 正式数据库迁移和部署产品化。

最需要优先处理的是 maintenance 二进制误提交风险和 Discovery 状态映射缺陷。完成仓库卫生、CI 和版本/文档一致性后，建议将当前证据工作台集合发布为 v0.3.0，把 Research Agent 单独归入 v0.4.0，而不是继续扩展 v0.2.x 补丁版本。
